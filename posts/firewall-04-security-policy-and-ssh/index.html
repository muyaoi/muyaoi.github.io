防火墙学习（四）：安全策略配置与 SSH 登录

发表于2026-09-27|更新于2026-09-27|防火墙
|浏览量:

系列收官篇，讲防火墙最核心的两件事。前半篇是安全区域与安全策略——防火墙区别于路由器的灵魂机制，搞懂它才算真正搞懂防火墙；后半篇把远程管理升级成加密的 SSH，替换掉明文的 Telnet，并记录 Windows 下连接老防火墙的两个经典报错的解法。

一、安全策略配置

三种安全区域

华为防火墙默认划分了三个安全区域，各自代表一种信任等级：

  • trust（受信任区）：放内部网络，对应公司内网；
  • dmz（隔离区）：放对外提供服务的服务器（Web、邮件等），内网外网都访问它，但它不能主动碰内网；
  • untrust（非受信任区）：放外部网络，通常是互联网出口方向。

加上代表防火墙自身的 local 区域，按优先级从高到低排：

优先级决定了流量的「默认态度」：从高优先级区域到低优先级区域算外出，反过来算进入。最关键的一条规则是——不同区域之间的流量默认全部拒绝，想通，必须由安全策略显式放行。这就是防火墙和路由器最大的区别：路由器看路由表，通了就转发；防火墙先看策略，不许可就不通。

踩坑一：连不上，报算法协商失败。 新版 Windows 自带的 OpenSSH 客户端默认禁用了 SHA1 系列的老密钥交换算法，而防火墙这类老设备只支持旧算法，两边谈不拢就握手失败。连接时手动把算法加回来即可：

踩坑二：报 HOST KEY VERIFICATION FAILED 或主机密钥变更警告。 之前连过同一 IP（比如重做过实验、换了设备），本地 known_hosts 里存着旧的主机密钥，与新设备对不上。清掉本地保存的旧密钥再连：

对比 Telnet 和 SSH 的配置清单，你会发现流程几乎一样（全局服务 → 接口服务 → 区域 → 策略 → VTY/AAA），SSH 只是多了一步 RSA 密钥对，再加上客户端侧的算法兼容问题。多付出的这几步，换来的是全程加密——这就是生产环境选 SSH 的理由。
