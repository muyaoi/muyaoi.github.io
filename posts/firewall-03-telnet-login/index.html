防火墙学习（三）：Telnet 远程登录防火墙

发表于2026-09-27|更新于2026-09-27|防火墙
|浏览量:

前两篇分别从 Console 口和 Web 界面摸到了防火墙，这篇换成网络工程师日常最常用的 Telnet 命令行。这次客户端不是本机浏览器，而是拓扑里的另一台路由器——从一台设备远程登录另一台设备，更接近真实的运维场景。Telnet 一共要过五道关：全局服务 → 接口服务 → 安全区域 → 安全策略 → VTY/AAA 认证，任何一环没配，登录都会失败。

实验拓扑

拓扑里加了一台路由器作为 Telnet 客户端，从它身上发起对防火墙的远程登录：

设置 IP 地址

给路由器和防火墙的互联接口分别配置 IP 地址，保证路由器和防火墙之间路由可达——连不通就谈不上远程登录：

开启 Telnet 服务并配置接口

华为设备的 Telnet 服务默认是关闭的，先在全局视图下把它打开，然后进入 GE1/0/0 接口设置 IP 地址：

再进入接口视图开启服务管理，服务状态指定为 telnet——相当于在这个接口上为 Telnet 流量开了一扇门：

划分安全区域

和上一篇一样，把 GE1/0/0 加入受信任区域（trust）。接口有了区域「身份」，经过它的流量才能被安全策略检查：

放行安全策略

这篇的新知识点在这里。路由器登录防火墙，Telnet 报文的目的地是防火墙本身，在防火墙的世界里这属于 local 区域——所以规则要设成源区域 trust、目的区域 local，并把流量放行：

这一步是 Telnet 实验里最容易漏的：防火墙对域间流量默认全部拒绝，没有这条 trust → local 的放行规则，后面 VTY 和 AAA 配得再对，登录请求也在门口被掐掉了。

配置 VTY 与 AAA 认证

进入 VTY 视图，允许 5 个用户同时登录（vty 0 4）、用户等级 3 级，并把认证方式指定为 telnet：

进入 AAA 认证视图，建立用户 whx，密码设置为加密方式存储的 whx@123456，等级 3 级，并开启 telnet 功能。密码用 cipher 加密存储后，配置文件里只能看到密文，看不到明文：

将建立的用户加入到系统用户下，账号才算正式生效：

远程登录测试

切到路由器上做测试，Telnet 远程登录到防火墙，输入 whx 账号和密码，能进入防火墙的命令行界面即为配置成功：

扩展：通过管理口 Telnet 登录

业务口走完了全套流程，那管理口呢？正好做个对照实验。

建立拓扑：

配置 IP 地址：

进入防火墙，全局开启 telnet 服务（已开就跳过），然后进入管理口 GE0/0/0 开启 telnet 服务：

注意这里不需要再划区域、配安全策略——管理口出厂已经把管理流量的路铺好了，这正是它和业务口的差别。用刚建好的 whx 用户即可直接登录到防火墙：

Telnet 登录防火墙的五道关：全局 telnet server enable → 接口 service-manage telnet permit → 接口划入区域 → trust→local 安全策略放行 → VTY + AAA 认证。排查登录失败时，按这个顺序逐层检查，一查一个准。
