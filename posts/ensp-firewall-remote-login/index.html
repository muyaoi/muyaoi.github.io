eNSP 配置华为防火墙的非 Console 口登录

发表于2026-09-06|更新于2026-09-06|学习笔记
|浏览量:

防火墙出厂默认只开放 Console 口，业务口全部处于关闭状态——这是它与路由器、交换机最大的区别。想通过 Web、SSH、Telnet 这些”非 Console”方式登录管理，必须先用 Console（或默认管理口）完成一轮初始化配置。本文记录在 eNSP 中用 USG6000V 完成这一过程的完整步骤。

一、环境准备

  • eNSP（需自行加载 USG6000V 设备包，否则防火墙启动报 40 错误）
  • 一台 USG6000V、一个 Cloud（云）设备用于桥接真实主机网卡
  • 真实主机上准备浏览器（Edge / Chrome 均可）和 SSH 客户端（PuTTY / Windows Terminal 的 ssh 命令）

USG6000V 的管理口 GE0/0/0 出厂自带 IP 192.168.0.1/24，默认账号 admin，密码 Admin@123，首次登录强制改密。

Console 口首次登录后系统会要求设置新密码，新密码必须满足复杂度：大写+小写+数字+特殊字符，且不含连续三个以上相同字符。

二、思路

非 Console 登录的本质是三件事：

  1. 给接口配 IP 并开启该接口的管理服务（service-manage）
  2. 放行安全策略——防火墙默认拒绝一切跨域流量，包括发往自身的管理流量（trust → local）
  3. 开启对应的服务并创建登录账号（Web / SSH / Telnet 各一套）

三、方式一：Web 界面登录

Web 登录依赖默认管理口，真实主机需与 GE0/0/0 同网段。在 eNSP 中用 Cloud 桥接主机网卡（UDP 或桥头绑定真实 NIC），主机 IP 配成 192.168.0.2/24，然后浏览器访问：

输入 admin / Admin@123，按提示修改密码后进入 Web 管理台。后续接口 IP、安全策略、服务配置都可以直接在 Web 界面完成，比命令行直观。

踩坑记录：浏览器提示”需授权 / 无法认证或认证失败”，基本都是下面两种情况：

  • 证书不受信任：USG 用的是自签名证书，点”高级 → 继续前往”即可；不要用 IE 内核兼容模式
  • 首次登录未完成强制改密：不完成改密流程，任何后续 API/页面请求都会被判定为未认证而失败

四、方式二：SSH（Stelnet）登录——推荐

先在 GE1/0/1 上起一个业务口作管理用（命令行以 Console 或 Web 登录后执行）：

为什么必须配 service-manage 和 trust→local 策略
  • service-manage enable 开启后，该接口默认拒绝所有管理类流量（ping/ssh/telnet/http），必须逐项 permit
  • 防火墙把”发给自己”的流量也归入安全策略检查（trust → local），不放行就连 ping 都不通
  • 这两步是初学者最常漏掉的，表现为”接口 IP 配了、线也连了，就是不通”

六、常见问题速查

现象 原因 解决
Web 页面”无法认证或认证失败” 自签名证书不被信任 / 未完成首次改密 继续前往；完成强制改密
ping 不通防火墙接口 未配 service-manage ping permit 接口下补配
SSH 能连上但认证失败 manager-user 密码复杂度不达标未生效 重新设置满足复杂度的密码
设备启动报 40 错误 未加载 USG6000V 镜像包 eNSP 里注册导入设备包

小结

记住三板斧：接口开服务（service-manage）→ 策略放行（trust→local）→ 服务端创建账号（aaa + vty）。三种非 Console 方式里，Web 适合看拓扑和调策略，SSH 适合日常命令行运维，Telnet 只在实验里玩玩就好。
